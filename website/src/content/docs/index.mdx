## How it works

<p class="ib-lead">One IvaraBase server manages one Postgres cluster. Each project inside it is isolated: its own database, role, keys, users, files and functions.</p>

<Steps>

1. **Run the server.** Start the container (or the binary) behind your proxy. Projects get their own address at `https://<project>.base.example.com`.

2. **Connect an agent.** Create a scoped access token (`read`, `write` or `admin`, optionally limited to some projects) and add the MCP endpoint to your client:

   ```sh
   claude mcp add --transport http ivarabase https://base.example.com/mcp \
     --header "Authorization: Bearer ivb_..."
   ```

3. **Ask for what you want.** *"Create a project called shop with products and orders tables, RLS so users only see their own orders, and a function that emails a receipt."* Anything destructive becomes an approval request you can accept from the UI, from your phone too, and every change lands in the audit log.

4. **Use it from your app** with the Supabase client you already know:

   ```ts
   import { createClient } from "@supabase/supabase-js";

   const supabase = createClient("https://shop.base.example.com", "<anon key>");
   const { data } = await supabase.from("orders").select("id, total, items(name)");
   ```

</Steps>

### What's in a project

| | |
|---|---|
| **Database** | Postgres 18, SQL editor, table editor, tracked migrations, generated TypeScript types, extensions (pgvector, pg_trgm, PostGIS, …) |
| **REST API** | `/rest/v1` through PostgREST: filters, embedding, RPC, upsert, row level security |
| **Auth** | Email/password, magic links and codes, phone (SMS), anonymous users, MFA (TOTP), Google, GitHub, Apple, any OpenID Connect provider |
| **Storage** | Buckets, RLS on files, signed URLs, resumable uploads (TUS), local disk or S3/R2/B2 |
| **Realtime** | Postgres changes (RLS-aware), broadcast and presence over `supabase.channel()` |
| **Functions** | TypeScript on Deno in Supabase's `Deno.serve` style, secrets, cron schedules, logs |
| **Webhooks** | Call a URL or a function on insert, update or delete, with retries and signatures |
| **Backups** | Encrypted `.ivbak` bundles, schedules, retention, restore tests, off-site S3, disaster recovery |
